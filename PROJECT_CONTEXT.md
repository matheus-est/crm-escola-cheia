# PROJECT_CONTEXT.md
> Last updated: 2026-04-01

## PROJECT
Multi-tenant CRM for school enrollment. Internal team (Master/Admin/Operations) manages multiple schools. Each school has a Manager/Commercial role accessing only their tenant.

Stack: PHP 8.4 · Laravel 13 · Inertia v2 · Vue 3 · Tailwind v4 · MySQL · Pest v4

## ACCESS PROFILES
ACL via `roles → permissions → Gate` — maintained intact from boilerplate.
Profile always via `users.role_id → roles.id`. No `role` ENUM column on `users`.

| Role slug | Type | Access |
|---|---|---|
| `master` | cross-tenant | Everything, only one who deletes School |
| `admin` | cross-tenant | Creates/edits Schools, manages users |
| `operacao` | cross-tenant | Read/write on tenants, no deletion |
| `gestor` | tenant-scoped | Everything in own tenant |
| `comercial` | tenant-scoped | Operational in own tenant, no config |

`User::isCrossTenant(): bool` — returns true if role is master/admin/operacao.

## MULTI-TENANCY
- Pivot `school_user` (`school_id`, `user_id`, `is_active`) — links gestor/comercial to tenants
- Cross-tenant does not need `school_user` — resolves tenant via `{school_uuid}` param
- `SetActiveTenant`: gestor/comercial via `school_user`; cross-tenant via `{school_uuid}`
- Link created on the School edit screen. Endpoint rejects role outside gestor/comercial with `ValidationException`

## STATUS FUNNEL

| # | Status | Type | Rule |
|---|---|---|---|
| 1 | `cadastro_inicial` | Entry | First status. Public form or manual creation |
| 2 | `agendamento` | Intermediate | Generated by Return Call tabulation |
| 3 | `visita` | Intermediate | Generated when attendance is confirmed |
| 4 | `matricula` | Terminal ✓ | Generated by Pre-Enrollment. Cannot be reopened |
| 5 | `recusado` | Terminal ✗ | Refusal on any task. Requires category + detail |

Refusal requires: `refusal_category` (`fatores_externos` / `fatores_internos` / `pedagogicos` / `administrativos`) + mandatory `refusal_detail`. `is_refusal = true` on outcome triggers validation in `TaskCompleteRequest`.

## TASK TYPES

| Enum | Schedule? | Generation |
|---|---|---|
| `retorno_ligacao` | No | First task — created manually when opportunity is created |
| `agendamento` | Yes ★ | Generated via Return Call tabulation |
| `lembrete_agenda` | Yes ★ | Generated automatically (1 day / half period before) |
| `reagendamento` | No | Generated by Did Not Attend or New Rescheduling |
| `double_check` | No | Generated to confirm attendance before visit |
| `provavel_matricula` | No | Generated automatically when visit is confirmed |
| `evento` | No | Generated when opportunity is linked to an Event |
| `lembrete_evento` | Yes ★ | Generated automatically before event |
| `reagendamento_evento` | No | Generated by Did Not Attend Event |
| `double_check_evento` | No | Generated for pre-event confirmation |

★ = `is_schedule = true` — appear in the calendar.

## RENITENTE CYCLE
`renitente_count` lives on `opportunities`.
count 0 → +1h · count 1–5 → +3h each · count 6 → `RenitenteLimitReachedException` + reset to 0

## OUTCOME MAP

**Return Call (retorno_ligacao)**
| Outcome | Actions |
|---|---|
| Renitente | `create_task(retorno_ligacao, renitente:true)` |
| Scheduling | `open_window(agendamento)` |
| New Return Call | `open_window(retorno_ligacao)` |

**Scheduling (agendamento)**
| Outcome | Actions |
|---|---|
| Attended | `move_status(visita)` + `create_task(provavel_matricula)` |
| Did Not Attend | `create_task(reagendamento, +2d)` |

**Schedule Reminder (lembrete_agenda)**
| Outcome | Actions |
|---|---|
| Will Attend | `create_task(lembrete_agenda)` |
| Will Not / Rescheduled | `cancel_tasks(lembrete_agenda)` + `open_window(agendamento)` |
| Renitente | `create_task(lembrete_agenda, renitente:true)` |

**Rescheduling (reagendamento)**
| Outcome | Actions |
|---|---|
| Rescheduled | `cancel_tasks(agendamento)` + `open_window(agendamento)` |
| Visit Done | `move_status(visita)` + `create_task(provavel_matricula)` |
| New Rescheduling | `open_window(reagendamento)` |
| Renitente | `create_task(reagendamento, renitente:true)` |

**Double Check**
| Outcome | Actions |
|---|---|
| Visited | `move_status(visita)` + `create_task(provavel_matricula)` + `cancel_tasks(agendamento)` |
| Did Not Visit | `cancel_tasks(agendamento)` + `open_window(agendamento)` |
| New Double Check | `open_window(double_check)` |
| Renitente | `create_task(double_check, renitente:true)` |

**Probable Enrollment (provavel_matricula)**
| Outcome | Actions |
|---|---|
| Pre-Enrollment | `move_status(matricula)` |
| In Progress with Future Date | `open_window(provavel_matricula)` |
| Probable | `create_task(provavel_matricula, +4d)` |

**Event (evento)**
| Outcome | Actions |
|---|---|
| Attended Event | `move_status(visita)` + `create_task(provavel_matricula)` |
| Did Not Attend Event | `create_task(reagendamento_evento, +2d)` |
| Did Not Attend, No Date | `cancel_tasks(evento)` |

**Event Reminder (lembrete_evento)**
| Outcome | Actions |
|---|---|
| Will Attend Event | `create_task(lembrete_evento)` |
| Will Not / Rescheduled | `cancel_tasks(lembrete_evento)` + `open_window(evento)` |
| Renitente | `create_task(lembrete_evento, renitente:true)` |

**Event Rescheduling (reagendamento_evento)**
| Outcome | Actions |
|---|---|
| Event Rescheduled | `cancel_tasks(evento)` + `open_window(evento)` |
| Attended Event | `move_status(visita)` + `create_task(provavel_matricula)` |
| Renitente | `create_task(reagendamento_evento, renitente:true)` |

**Event Double Check (double_check_evento)**
| Outcome | Actions |
|---|---|
| Visited Event | `move_status(visita)` + `create_task(provavel_matricula)` + `cancel_tasks(evento)` |
| Did Not Visit Event | `cancel_tasks(evento)` + `open_window(evento)` |
| Renitente | `create_task(double_check_evento, renitente:true)` |

**Any task — Refusal**
| Outcome | Actions |
|---|---|
| Refusal | `move_status(recusado)` — requires category + detail |

## ARCHITECTURE DECISIONS

- RabbitMQ removed — `QUEUE_CONNECTION=database`
- Check `resources/js/components/ui/` and `composables/` before creating anything new

## CORRECTED DEVIATIONS

**`currentSchool()` without School model available**
Use `class_exists(\App\Models\School::class)` before referencing the model.

**`SegmentSeeder` not idempotent for UUID**
Use `firstOrCreate()` — never `updateOrCreate()` with UUID as second argument (overwrites on every run).

**`RoleSeeder` from boilerplate uses `sync()`**
Known technical debt — do not fix to avoid changing boilerplate code outside scope.

**`OutcomeSeeder`: spec says 30 normal outcomes, tables list 31**
Implementation follows the tables (31 + 10 refusals = 41). Tables represent correct domain behavior.
